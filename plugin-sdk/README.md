# ダンおに譜面エディタ プラグインSDK

外部制作者がプラグインを開発するために必要なものを一式まとめたフォルダです。このフォルダさえあれば、
本体のリポジトリ全体にアクセスしなくてもプラグイン開発を始められます。

## 中身

| ファイル/フォルダ | 内容 |
|---|---|
| `DanoniEditor.PluginContracts.dll` | プラグインが参照する契約(インターフェース・型)。エディタ本体をビルドするたびに自動的に最新化されます。 |
| `template/` | プラグインの雛形。コピー&リネームして使い始められます。 |
| `sample/` | 動作する実例(HandMovementSamplePlugin)。API一式の使い方を実際のコードで確認できます。 |
| `docs/plugin_api_reference.md` / `.html` | APIリファレンス。まずはこれを読んでください。 |

## 使い方

1. `template/` フォルダをまるごとコピーし、好きな名前にリネームします(例: `MyAwesomePlugin/`)。
2. コピーした中の `PluginTemplate.csproj` と `MyPlugin.cs` を、プラグインの内容に合わせて書き換えます
   (ファイル名・クラス名も自由に変更して構いません)。`MyPlugin.cs`内のTODOコメントを参照してください。
3. `dotnet build` でビルドします。
4. 出力された `.dll`(自分の書いたプラグイン本体)を、エディタ本体のexeと同じ階層にある `plugins`
   フォルダへコピーします(無ければ新規作成してください)。
   - NuGetパッケージ等の外部ライブラリに依存している場合は、出力フォルダにある依存DLL一式と
     `(プラグイン名).deps.json` も一緒にコピーしてください(エディタ側が.deps.jsonを読んで
     依存を解決します)。
   - `DanoniEditor.PluginContracts.dll` はコピー不要です(コピーしても無視され、常に本体側の
     ものが使われます)。
5. エディタを起動し直すと、プラグインが読み込まれます。

## 動作確認・トラブルシューティング

- プラグインの読み込み状況(成功/失敗の詳細)は、`plugins/plugin_log.txt` に記録されます。
  読み込まれない・動作がおかしい場合は、まずこのログを確認してください。
- 読み込みに失敗したプラグインがあった場合、エディタ起動時にダイアログでも通知されます。
- パネル描画中・オーバーレイ描画中の例外は、エディタ本体を巻き込まないようその場で握りつぶされます
  (該当プラグインの表示だけがスキップされます)。原因調査は上記のログを頼りに行ってください。
- `sample/` の `HandMovementSamplePlugin.cs` は、右パネルへのタブ差し込み・譜面ビューへのオーバーレイ
  描画・ノート配置APIの3点全てを実際に使い切っているので、実装の参考にしてください。

## 互換性の保証

エディタ本体側は、一度公開したプラグインAPIについて以下を約束します(追記専用ポリシー)。

- 公開済みのインターフェース・型・メンバーの削除・改名・シグネチャ変更は行いません。
  機能追加は「新メンバー・新型の追加」だけで行います。
- プラグインが実装するインターフェース(`IEditorPlugin`等)へメンバーを追加する場合は、
  必ず既定実装付きで追加します。**古いバージョンのSDKでビルドしたプラグインDLLは、
  再ビルド不要のまま新しいエディタでも動き続けます。**
- `DanoniEditor.PluginContracts.dll` のアセンブリバージョンは固定されており、
  バージョン不一致による読み込み失敗は発生しません。

## 制約(現時点)

- プラグインの有効/無効切替・アンインストール・ホットリロードといった運用機能はありません
  (`plugins`フォルダへのDLL配置がそのまま有効化を意味します)。
- 譜面データの書き換えは、現状「通常ノートの配置/削除」のみに対応しています(段階2の最小構成)。
- 判定ロジック・ゲージ計算式・マウス操作の基本挙動といった、エンジンの中核的な挙動を差し替える
  APIは提供していません。

詳細な仕様は `docs/plugin_api_reference.md` を参照してください。
