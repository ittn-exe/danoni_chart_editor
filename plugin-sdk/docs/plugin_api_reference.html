🐱 プラグインってなに?

エディタ本体を改造せずに、あなたの作った機能をエディタへ「後付け」できる仕組みです。作ったプラグインは1個のファイル(.dll)になり、エディタのpluginsフォルダへ置くだけで動きます。

プラグインができることは、今のところ大きく3つです。

できること例
右パネルに自分のタブ(画面)を追加する設定画面、解析結果の表示
譜面ビューの上に好きな図形・文字を重ねて描く「ここが右手移動だよ」のマーク表示
譜面にノートを置く/消すパターン自動配置(Ctrl+Zで取り消せる形で)
🐾 逆に、判定の仕組みやゲージ計算などエディタの中身そのものを書き換えることはできません。「読む・見せる・ちょっと書く」が守備範囲です。

🐱 準備するもの

  1. Windowsのパソコン(エディタ本体が動く環境)
  2. .NET 8 SDK — 公式サイトから無料で入手できます。インストール後、コマンドプロンプトでdotnet --versionと打って数字が出ればOKです
  3. plugin-sdkフォルダ — エディタの配布元から受け取ってください。この中に必要なもの(参照用DLL・雛形・サンプル・この文書)が全部入っています
  4. (あると便利)Visual Studio または VS Code — 無くてもメモ帳とコマンドだけで作れますが、あると入力補完が効いて楽です
🐾 C#というプログラミング言語で書きます。「クラス」「メソッド」が何かくらいの知識があれば大丈夫です。わからなくなったらsampleフォルダの実物を真似してください。

🐱 はじめてのプラグイン(5分コース)

1雛形をコピーする
plugin-sdk/template/フォルダをまるごとコピーして、好きな名前(例: MyFirstPlugin)にリネームします。

2名前を決める
コピーした中のMyPlugin.csを開き、Id(他の人と被らないID)とName(表示名)を書き換えます。

public string Id => "neko.myfirstplugin";  // ← 自分だけのIDに
public string Name => "はじめてのプラグイン"; // ← 好きな表示名に

3ビルドする
コピーしたフォルダの中でコマンドを1つ打ちます。

dotnet build

成功するとbin\Debug\net8.0-windows\の中に(プロジェクト名).dllができています。

4エディタに置く
できた.dllを、エディタ本体(exe)と同じ場所にあるpluginsフォルダへコピーします。pluginsフォルダが無ければ自分で作ってください。

5エディタを起動する
右パネルに「マイプラグイン」というタブが増えていたら成功です。おめでとうございます!

🐾 雛形は「そのままビルドしても一応動く」状態になっています。まず何も書き換えずに手順3〜5を試して、動くことを確かめてから改造を始めるのがおすすめです。

🐱 パネルに何か表示する

右パネルのタブの中身はCreatePanel()で作ります。WPFの部品(TextBlock、Buttonなど)を組み合わせて返すだけです。

public UIElement CreatePanel()
{
    var panel = new StackPanel { Margin = new Thickness(8) };
    panel.Children.Add(new TextBlock { Text = "こんにちは、プラグインです!" });
    return panel;
}

「今開いている譜面の情報」は_host.CurrentChartから取れます。譜面が切り替わったり編集されたりしたときはChartChangedイベントが飛んでくるので、表示を更新したい場合はこれを購読します。

public void Initialize(IPluginHost host)
{
    _host = host;
    host.ChartChanged += () =>
    {
        var chart = host.CurrentChart;
        if (chart is null) return; // プロジェクトが開かれていない時はnull
        // 例: レーン数やノート数を数えて表示を更新する
    };
}
🐾 CurrentChartはnullのことがある(プロジェクト未オープン時)ので、必ずnullチェックしてから使ってください。これを忘れるのが一番よくあるつまずきポイントです。

🐱 譜面に何か描く

RenderOverlayは譜面ビューが描き直されるたびに呼ばれます。transformがtick(時間)とレーン番号を画面の座標へ変換してくれるので、あとは好きな図形を描くだけです。

public void RenderOverlay(DrawingContext dc, PluginChartViewTransform transform, PluginChartContext? chart)
{
    if (chart is null) return;

    // 例: レーン0の全ノートの位置に、半透明の水色の丸を重ねる
    var brush = new SolidColorBrush(Color.FromArgb(0xA0, 0x40, 0xC0, 0xFF));
    double x = transform.LaneToScreenX(0);           // レーン0の中心X座標
    foreach (var tick in chart.Lanes[0].NoteTicks)
    {
        double y = transform.TickToScreenY(tick);    // そのノートのY座標
        if (y < 0 || y > transform.ViewportHeight) continue; // 画面外なら描かない
        dc.DrawEllipse(brush, null, new Point(x, y), 6, 6);
    }
}
🐾 「画面外なら描かない」の1行は必ず入れてください。長い曲でこれを忘れると、見えないところまで全部描こうとして動作が重くなります。

🐱 ノートを置いてみる

_host.Editからノートを置いたり消したりできます。この方法で置いたノートは、ユーザーがCtrl+Zで取り消せます。

// レーン0の先頭(tick 0)にノートを置く。置けたらtrueが返る
bool ok = _host.Edit.PlaceNote(laneIndex: 0, tick: 0);

// 消すのはこちら
_host.Edit.DeleteNote(laneIndex: 0, tick: 0);

「すでにノートがある場所に置こうとした」「そこにノートが無いのに消そうとした」場合は、何も起きずにfalseが返ります。エラーにはならないので安心してください。

🐾 tickは時間の単位です(1拍=1680tick)。「◯小節目の頭」のような位置を計算したい場合は、4/4拍子なら1小節=6720tickと覚えておくと便利です。

🐱 動かないときは

症状確認すること
タブが増えない/何も起きないplugins/plugin_log.txtを開いてください。読み込みの成功・失敗が全部書いてあります
起動時に警告ダイアログが出たダイアログの内容とplugin_log.txtに失敗理由が書いてあります(ビルドし忘れ・古いdllのままが定番です)
NuGetパッケージを使ったら動かなくなった出力フォルダにある依存DLL一式と(名前).deps.jsonも一緒にpluginsへコピーしてください
パネルやオーバーレイが途中で表示されなくなったプラグイン内で例外(エラー)が起きています。plugin_log.txtに記録されているので内容を確認してください
直したのに変わらないエディタは起動時にしかプラグインを読みません。dllを差し替えたらエディタを再起動してください
🐾 DanoniEditor.PluginContracts.dllはpluginsフォルダへコピーしなくて大丈夫です(コピーしても無視されます)。

読み込みの仕組み

  • 本体の起動時に./pluginsフォルダ(exeと同じ階層)直下の*.dllを全て読み込み、IEditorPluginを実装し、かつ引数無しの公開コンストラクタを持つ型を自動的にインスタンス化します。
  • プラグインDLLはそれぞれ専用のAssemblyLoadContextで読み込まれます。
  • 依存DLLの解決: ①プラグインの.deps.json(あれば)→②プラグインと同じフォルダ、の順で自動解決されます。
  • 契約DLLの扱い: DanoniEditor.PluginContractsへの参照は常に本体側の読み込み済みインスタンスへ委ねられます(型不一致事故の防止)。
  • 診断ログ: 読み込みの成功/失敗、初期化失敗、描画中の例外は全てplugins/plugin_log.txtへ記録されます。
  • 1つのDLL・型の失敗は他のプラグインの読み込みを妨げません。ホットリロード・有効/無効切替UIはありません(DLL配置=有効化、反映には再起動が必要)。

基底インターフェース: IEditorPlugin

public interface IEditorPlugin
{
    string Id { get; }       // 一意なID(半角英数字推奨、他プラグインと重複させない)
    string Name { get; }     // UI上に表示するプラグイン名
    string Version { get; }  // 表示用のバージョン文字列(本体側は検証しない)
    void Initialize(IPluginHost host);  // 読み込み直後に一度だけ呼ばれる
}

これ単体では何もしません。下記の派生インターフェースを1つ以上組み合わせて実装します(1つのプラグインが複数を同時に実装しても構いません)。

UIパネル差し込み: IEditorPanelPlugin

public interface IEditorPanelPlugin : IEditorPlugin
{
    string PanelTitle { get; }      // 右パネルのタブ見出し
    UIElement CreatePanel();        // タブの中身(WPF UIElement)を1つ生成する
}
  • 本体はCreatePanel()の戻り値をそのまま右パネルのTabItem.Contentへ設定します。内部のレイアウト・状態管理は全てプラグイン側の責任です。
  • 呼ばれるのはアプリ起動時に1回だけです。以後の表示更新はIPluginHost.ChartChangedを購読して行います。

譜面ビューへのオーバーレイ描画: IChartOverlayPlugin

public interface IChartOverlayPlugin : IEditorPlugin
{
    void RenderOverlay(DrawingContext dc, PluginChartViewTransform transform, PluginChartContext? chart);
}
  • 譜面ビューの再描画のたびに、本体の描画が完了した後、最前面に呼び出されます。
  • chartはプロジェクト未作成・タブ未選択の場合nullになりえます。
  • 描画中の例外は本体を止めず、plugins/plugin_log.txtへ記録された上でその回の描画だけスキップされます。
  • 呼び出し頻度: 固定fps(毎フレーム等)での呼び出しではありません。WPFのOnRenderパス、つまりInvalidateVisual()が呼ばれた時にのみ発生します。スクロール・ズーム・ノート編集・選択操作・Undo/Redo・プロジェクト読み込みなど、譜面ビューの見た目が変わりうる操作のたびに呼ばれる仕組みのため、実運用では「操作されるたびに数回〜」程度の頻度になります。重い処理を書く場合はこの前提で計測してください。
  • 複数プラグイン間の描画順: 明示的な優先度指定はありません。pluginsフォルダ内のDLLファイル名を英数字順(大文字小文字を区別しない)に並べて読み込むため、オーバーレイもその順で呼び出されます。重なりの順序を制御したい場合はファイル名の先頭に連番などを付けてください。

PluginChartViewTransform(座標変換)

public sealed class PluginChartViewTransform
{
    public Func<long, double> TickToScreenY { get; }   // tick → 譜面ビュー上のY座標(px)
    public Func<int, double> LaneToScreenX { get; }     // レーンindex(0始まり) → レーン列の中心X座標(px)
    public double NoteLaneWidth { get; }                // ノートレーン1本分の幅(px)
    public double ViewportWidth { get; }                // 表示中ビューポート幅(px)
    public double ViewportHeight { get; }               // 表示中ビューポート高さ(px)
    public bool IsReverse { get; }                       // Reverse表示が有効か
}

IPluginHost(本体とのやり取りの入口)

public interface IPluginHost
{
    PluginChartContext? CurrentChart { get; }
    IPluginEditApi Edit { get; }
    event Action? ChartChanged;
    string? GetPluginData(string key);
    void SetPluginData(string key, string value);
}
メンバー内容
CurrentChart呼び出しのたびに最新の読み取り専用スナップショットを返す。プロジェクト未作成・タブ未選択の場合はnull
Edit譜面データを書き換えるための限定API(下記)
ChartChangedプロジェクト・難易度タブの切替や譜面編集のタイミングで発火。表示更新のトリガーに使う
GetPluginData / SetPluginDataプラグイン専用データのプロジェクトファイルへの永続化(下記)

ChartChangedの発火条件: 譜面の状態が変わりうる操作のほぼ全てで発火します。ノート配置・削除等の編集操作(プラグイン自身のEdit.PlaceNote/DeleteNote経由の変更も含む)、Undo・Redo、難易度タブの切替・追加・削除・並び替え・複製、BPM等ヘッダー値の直接編集、キー種変更、Reverse切替、プロジェクトの新規作成・オープン・保存完了・クローズ、プラグイン自身のSetPluginData呼び出し、などが対象です。選択操作など軽微な操作でも発火しうるため、呼び出し頻度が高くなる前提でハンドラを書いてください(重い処理を避ける、または前回スナップショットとの差分検知を行う)。

編集API: IPluginEditApi

public interface IPluginEditApi
{
    bool PlaceNote(int laneIndex, long tick);   // 通常ノート配置(成功でtrue)
    bool DeleteNote(int laneIndex, long tick);  // 通常ノート削除(成功でtrue)
}
  • 本体のUndo/Redoスタックへ正しく積まれるため、プラグインによる変更もユーザーがCtrl+Zで取り消せます。
  • 配置先に既にノートがある・対象が無い・レーン/tickが不正・プロジェクト未作成、の場合はfalseを返し何もしません。
  • 現状は「通常ノートの配置/削除」のみです。拡張は要望に応じて行います。
  • 座標範囲の詳細: laneIndexは0以上、現在の難易度タブのレーン数未満(固定値ではなくキー種によって変わります)。範囲外はfalse。tickはPlaceNoteではtick < 0のみ弾かれ、上限チェックはありません(曲の長さを超える値も配置自体は成功しえます)。DeleteNoteはtickの範囲チェック自体を行わず、対象位置に既存ノートがあるかどうかのみで判定します。

データ型

PluginChartContext(現在の難易度タブの読み取り専用スナップショット)

public sealed class PluginChartContext
{
    public string KeyTypeId { get; }
    public string DifficultyName { get; }
    public IReadOnlyList<PluginLaneInfo> Lanes { get; }
    public Func<long, double> TickToFrame { get; }
    public Func<double, long> FrameToTick { get; }
}

PluginLaneInfo(1レーン分の情報)

public sealed record PluginLaneInfo(
    string LaneId,
    string KeyAssign,                              // プレイテスト時の割当キー("/"区切り)
    int ColorGroup,
    IReadOnlyList<long> NoteTicks,
    IReadOnlyList<(long Start, long End)> FreezeTicks);

本体内部のモデルを直接公開せず、この形へ変換した上で渡しています。内部実装がどう変わってもこのデータ型自体は維持されます。

データ永続化

GetPluginData/SetPluginDataは、プロジェクトファイル内の自由記述領域を、呼び出し元プラグインのIDで自動的に名前空間分け("{プラグインID}.{key}")した上で読み書きします。

  • 値は文字列のみです(構造化データはJSON文字列にして保存してください)。
  • dos.txtへは出力されません。エディタのプロジェクトファイル内だけに保存されます。
  • 本体はこの中身を一切解釈しません。

互換性の保証

エディタ本体側は追記専用(append-only)ポリシーを採用しており、以下を約束します。

  • 公開済みのインターフェース・型・メンバーの削除・改名・シグネチャ変更は行いません。機能追加は「新メンバー・新型の追加」だけで行います。
  • プラグインが実装するインターフェースへのメンバー追加は必ず既定実装付きで行うため、古いSDKでビルドしたプラグインDLLは、再ビルド不要のまま新しいエディタでも動き続けます。
  • DanoniEditor.PluginContracts.dllのアセンブリバージョンは固定されており、バージョン不一致による読み込み失敗は発生しません。

制約・注意点

  • 全API呼び出しはUIスレッド(WPFのDispatcherスレッド)上で行われる想定です。バックグラウンドスレッドを使う場合、UI操作・ホストAPI呼び出しは必ずUIスレッドへディスパッチしてください。
  • 判定ロジック・ゲージ計算式・マウス操作の基本挙動・ノート自体の描画方法など、エンジン中核の差し替えAPIは提供していません。
  • プレイテスト画面へのオーバーレイは未対応です(現状は譜面ビューのみ。将来課題)。
  • プラグインの有効/無効切替・アンインストール・ホットリロードといった運用機能はありません。

付属サンプル: HandMovementSamplePlugin

plugin-sdk/sample/に同梱されています。IEditorPanelPlugin・IChartOverlayPluginの両方を実装し、右パネルタブ・オーバーレイ描画・ノート配置API・ChartChanged購読の一通りを実際に使っています。

  • 右パネルに「右手移動(サンプル)」タブを追加し、現在のキー種・難易度名・レーン数を表示
  • 「レーン0 tick0 にテスト配置」ボタンでPlaceNoteを実行(Undo対応)
  • 譜面ビューへ、後半半分のレーンのノート位置に丸印をオーバーレイ描画
