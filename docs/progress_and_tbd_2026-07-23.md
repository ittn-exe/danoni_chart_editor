## 1. 実装済み機能(全体)

### コア設計

- tickベースのタイミング管理(`TimingEngine`)、tick↔frame変換、拍子/BPM変化点対応
- テンプレート形式(`./template/temp_{keyTypeId}.json`、`KeyTemplate`/`LaneDef`)。24キー種分を収録
- プロジェクトファイル形式(JSON、`ProjectSerializer`、schemaVersion移行対応)
- Undo/Redo(`IEditAction`/`CompositeEditAction`/`UndoStack`、保持件数を環境設定で変更可)
- FUJIエディタ形式・SKBエディタ形式・dos.txt単体のインポート/エクスポート
- D&Dによるファイル読み込み(自形式/FUJI/SKB/dos.txt/BASE64楽曲データ/生音源ファイルを中身から判定)

### 譜面編集エリア

- マウスモード(スマートツール/個別ツール)・SKB操作モード(キーボード入力)の両対応
- キーボードモードの小節移動・現在位置ライン自動スクロール(譜面ビューのReverse設定に追随)
- ncolor_data個別色編集モード(通常色/ヒット時色/塗りつぶし色、一括塗り、履歴)
- コメント・警告(Annotations)。インポート時の丸め処理等を自動記録し、警告アイコンを譜面ビューに重ね描き
- 範囲選択・クリップボード(プロジェクトを跨いだ貼り付け)・全選択(Ctrl+A/Shift+Ctrl+A対象種別を環境設定で選択可)
- フレーム情報モード(拍情報モードとの相互変換)
- レーン入替マクロ(仕様書11章): `MacroEditorWindow`で順列を定義し、右パネルから実行(Undo対応)
- **拍子レーンのオブジェクト右パネル編集(新規)**: 拍子オブジェクトを配置した後、右パネルで分子・分母を直接編集可能に(`PlaceTimeSignatureAction`を再利用)
- **各レーンのノート数リアルタイム表示(新規)**: 上部パネルのトグルボタン(既定OFF)で切替。マウスモードはレーンラベルの2行目、キーボードモードは1行目を差し替えて表示

### プレイテスト・目視テスト

- プレイテスト画面(判定・コンボ表示、オートプレイ、ハイスピード/オフセット/ウィンドウ倍率、中断キー選択、speed_data/boost_data反映)
- 目視テスト(再生位置ラインの追従方式選択: ページ送り/スムーズスクロール)
- 再生速度・音量の共通設定(スライダー+数値入力欄、プレイテストにも反映)
- **キー種ごとのプレイテストReverse既定値(新規)**: 環境設定でキー種ごとにReverse既定ON/OFFを設定でき、難易度タブ切替時に自動反映

### 右パネル/環境設定/その他UI

- プロジェクトプロパティ・色設定・選択中オブジェクト・その他ヘッダー(カテゴリ別折りたたみ)の4タブ構成
- 右パネルの自動切り替えは「単体オブジェクトをクリックした時のみ」に限定
- 環境設定ウィンドウ(カテゴリ式、表示/目視テスト/プレイテスト/新規プロジェクト/編集保存/キーボードモード/musicURL取得/テンプレート)
- `TemplateEditorWindow`(テンプレート新規作成・編集): レーンごとのタブ編集・D&D並び替え・プレビュー帯・`fujiLaneNum`入力欄
- musicURLからの楽曲自動取得機能、最近開いたファイル、起動スプラッシュウィンドウ
- **右パネルの幅リサイズ(新規)**: 譜面ビューと右パネルの境界を`GridSplitter`でドラッグ可能に
- **右パネル入力欄のEnterキー確定(新規)**: 単一行入力欄(TextBox/ComboBox)はEnterキーでLostFocus相当の即時確定が可能に。複数行入力(`ObjectCommentBox`等、`AcceptsReturn="True"`)は対象外、上部ツールバー(音量/プレイテストオフセット等)も対象外
- **難易度タブバーへの「新規譜面を追加」ボタン(新規)**: プロジェクト新規作成時と同じダイアログを表示し、その内容でカレントプロジェクトにタブを追加
- **ツール値(難易度)の表示(新規)**: 右パネル・プロジェクトタブに「ツール値(難易度、参考値)」を追加。danoniplus本体の「レベル計算ツール++」(`calcLevel`)アルゴリズムを`danoni_main.js`から移植して算出
- **プロジェクト名表示の不具合修正**: タイトルバー・プロジェクトタブが保存/読み込み後も「untitled」のままだった不具合を修正。ファイル保存・読み込み時に`ProjectName`を実ファイル名(拡張子除く)へ同期するよう修正

### ゲージ設定(customGauge/gaugeXXX)

- `GaugeEditorWindow`(設定メニューから起動)
  - ①難易度タブごとのゲージ名リスト編集(「指定しない」「継承キーワード(survival/border/customDefault)」「明示リスト(name::F|V::表示名)」の3択)
  - ②ゲージ別パラメータ(ノルマ/回復/ダメージ/初期ライフ)をプロジェクト全体で共有するテーブル形式で編集
  - ③直接入力モード: dos.txtのゲージ関連ヘッダー行をそのまま貼り付け可能(過去資産からのコピペ用途)
- **ゲージ計算機(新規)**: `GaugeEditorWindow`から非モーダルで起動する`GaugeCalculatorWindow`
  - カレントタブのゲージ設定を基に計算。ウィンドウ表示中に(ゲージ編集ウィンドウ内の)タブが切り替わった場合は新しいタブの数値で自動再計算(警告なし)
  - 「対象ゲージ名」欄はプロパティテーブルの該当セルと連動して読み書き
  - Fix/Varyモードは自動判定するが、常にユーザー側で上書き可能
  - デザインモード(逆算機能)を実装: 目標値(クリア率/ミス数)から回復量・ダメージ量を逆算
  - 実装にあたり、ユーザー提供の参考ツール(calc.html)にあったFixモードの計算式バグ(`realRcv`を100倍していた誤り)を、danoniplus本体の実ソース(`calcLifeVal`)との突き合わせで発見・修正済み

### imgフォルダの画像対応

- **SVG対応(新規)**: ノート画像素材としてpngの代わりにsvgファイルを配置可能に(pngが優先、無い場合にsvgをラスタライズして使用)。`Svg`パッケージ使用。ラスタライズ処理はWindowsランタイム依存(Linux環境では`PlatformNotSupportedException`になることをサンドボックスで確認済み。既存の「実行はWindowsのみ」という設計と整合)

### FUJIエディタ形式インポートの精度向上

ユーザー提供の実サンプルとの突き合わせで発見・修正した3件のバグ(フリーズ終点位置の解釈・進数解釈・`T`/`X`の固定値化)。詳細は`docs/fuji_format_notes.md`参照。

### 2-5. 歌詞表示機能(word_data)未対応

仕様: [dos-e0003-wordData](https://github.com/cwtickle/danoniplus/wiki/dos-e0003-wordData)。ステップゾーン上下に表示する歌詞テキストを、フレーム位置ごとに設定する機能(`word_data`)。

- 1エントリ = `Frame, Position(偶数=上段/奇数=下段), Lyrics` の3項目。改行区切り。
- 制御用エントリとして`[fadein]` `[fadeout]` `[left]` `[center]` `[right]` `[fontSize=XX]`のキーワード行や、`-`(コメント専用行)もある。
- データ名は用途別に多数存在(`word_data`/`word2_data`/`wordRev_data`/`wordAlt_data`・`wordCross_data`/`wordJa_data`・`wordEn_data`/`wordA*_data`等)。優先順位ルールも存在(最大8段階)。

エディタ側の対応方針(ユーザー要望): 任意に利用可能な「歌詞入力レーン」を設け、既定OFF・上部パネルのトグルボタンで表示/非表示を切り替え。レーン上にオブジェクトとして歌詞を配置・編集できる形を想定。データ名のバリエーションまで全対応するか、まずは基本の`word_data`/`wordRev_data`のみ先行対応するかは実装時に要検討。

### 2-6. カレント難易度タブのみをdosエクスポート(合作用)

複数人で1曲を分担制作する「合作」用途で、プロジェクト全体ではなく現在開いている難易度タブ1つ分だけをdos.txtとして書き出す機能。単体タブ出力時はサフィックス番号を持たない(先頭タブ相当の無サフィックス形式に振り直す)想定。

ユーザーからの検討事項: エクスポート時に何を含めるか(サフィックス採番のやり方、その他ヘッダー・共通設定をどこまで含めるか等)をチェックボックスで選べるようにすべきか、という論点が未確定。実装時に具体的な選択項目を洗い出して決める必要がある。

### 2-7. その他

- 仕様書14章「今後追加される項目の反映」は元々オープンエンドな項目だったが、headerDefaults・colorHistory・macros・undoHistorySizeは全て実装済み。今後新たに項目が増えた場合もこの方針(AppSettings/専用ファイルへの追加)を継続する想定。

## 3. 将来実装の可能性(TBDとは別枠)

以下は「今は実装しないが、需要があれば将来実装する可能性がある」項目。TBD(未解決の実装課題)とは異なり、現時点で着手予定が無いことが確定している事項。

1. **FUJIエディタへのエクスポート機能**: 現段階では実装予定なし。当エディタはFUJI/SKB形式に対して現状「インポートのみ」対応。
2. **SKBエディタへのエクスポート機能**: 同上、現段階では実装予定なし。
3. **ラベル密集時の省略表示**: speed/boost/BPM等のイベントタグが密集した際の省略表示。監視コストに見合う需要が今のところ無く、必須機能とはしない。
4. **テンプレートエディタによる(CW Edition本体で使う)"カスタムキーテンプレート作成"機能**: 当エディタの`TemplateEditorWindow`で作成したテンプレートを、danoniplus本体(CW Edition)側の「カスタムキーテンプレート」としてもそのまま使える形で書き出す機能。「エディタでテンプレを作ったのに本体用のテンプレをもう1回作るのが面倒」という動機。現時点では必要性が低いため着手せず、将来実装の可能性としてのみ記録する。

## 4. 配布形態についての確認結果

`dotnet publish -r win-x64 -p:PublishSingleFile=true --self-contained true`で実際にpublishし、出力フォルダの中身を確認した。結果、**単独EXEファイルのみでの配布は不可能**で、以下のファイルがexeと同じフォルダに残る:

- `D3DCompiler_47_cor3.dll`
- `PenImc_cor3.dll`
- `PresentationNative_cor3.dll`
- `vcruntime140_cor3.dll`
- `wpfgfx_cor3.dll`

これはWPF(Windows Desktop)アプリ全般に共通する.NET SDK側の既知の制約で、self-contained + single-file publishを行っても、上記のネイティブ相互運用DLL群だけは単一exeに埋め込めず、必ず別ファイルとして出力される仕様(当エディタ固有の問題ではない)。

加えて、`template`フォルダ(24キー種分のテンプレートJSON)は`.csproj`の設定により常にexeと同じ階層へコピーされる。`img`フォルダ(png/svg共)はリポジトリに存在しない場合はコピーされない(`Condition="Exists('..\..\img')"`)ため、想定通り「imgフォルダの中身はエディタ利用者が用意する」前提のままで問題ない。

まとめると、公開時のZIP等には最低限「exe本体+上記5個の付随DLL+templateフォルダ」を含める必要があり、「EXEファイル単体」での配布はできない。
