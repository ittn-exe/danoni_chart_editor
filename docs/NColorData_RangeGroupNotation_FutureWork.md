# ncolor_data 範囲指定・グループ指定 対応メモ(将来実装検討用)

作成日: 2026-07-23
対象: 色編集モード(ncolor_data)

## 現状の対応範囲

本エディタの色編集モードは、`ncolor_data`のColorNo欄に「個別矢印番号1つ(EngineLaneNum)」のみを出力する。
本家dos.txt仕様(dos-e0002-ncolorData)にある以下の省略記法には対応していない。

- 連続範囲指定: `0...7`
- スラッシュ区切り複数指定: `1/3/5/7`
- グループ指定: `g0`〜`g9`(キーコンフィグのグループ)、`all`(全グループ)

`DosImporter.ImportNColorData`は、これらの記法を含む行を「個別ノートの色として読み込めない」ものとして安全にスキップし、件数を警告として表示する実装になっている(データの握りつぶしはしない)。

## 対応を見送った理由

これらは人力でdos.txtを直接記述する際の省力化のための略記であり、GUIエディタでは「複数選択→一括塗りつぶし」機能で同じ結果(対象ノート全てに同一色を適用)を実現できるため、優先度を下げた。

ただし一括塗りつぶしは対象ノート数だけ`ncolor_data`の行を出力するため、範囲/グループ指定を使った場合より出力が冗長になる(実行結果は同じだが、dos.txtの可読性・行数は劣る)。

## 将来実装する場合の方針案

- **出力の圧縮**: 一括塗りつぶし時、対象が同一レーンで連続するtick(≒EngineLaneNumが連番)であれば`0...7`相当へまとめる最適化を検討する。ただしEngineLaneNumが連番でない特殊テンプレートでは範囲指定の意味が本家側の想定と食い違う可能性があるため、実装前に該当テンプレートの有無を要確認。
- **グループ指定(`g0`〜`g9`)**: 本エディタのColorGroup(色設定タブの色グループ)と、キーコンフィグ側のグループ番号が一致する保証が無いため、対応するなら先に両者の対応関係を検証する必要がある。
- **インポート側の拡張**: 将来ColorNoの範囲/グループ表記を編集可能にする場合、`NColorEntry`(現在はノート/フリーズの実体に1:1で紐付くtickキー方式)のモデル自体を「範囲・グループを表す抽象的な色変化イベント」を扱える形へ拡張する必要がある。現状のノート単位モデルとは設計思想が異なるため、片手間の追加ではなく再設計に近い作業になる見込み。
