## 3. ビルド・テスト手順(サンドボックス環境)

**環境はLinuxサンドボックス。毎回のセッションで.NET SDKが消えている可能性がある**
(本スレッドでも作業途中でSDKが消失し、再インストールが必要になった)。

### 3.1 SDKが無い場合の再インストール

```bash
mkdir -p /tmp/dnxtmp
cd /tmp && curl -sSL https://dot.net/v1/dotnet-install.sh -o dotnet-install.sh \
  && chmod +x dotnet-install.sh \
  && TMPDIR=/tmp/dnxtmp ./dotnet-install.sh --channel 8.0 --install-dir /tmp/dotnetsdk
```

**注意**: 既定の `TMPDIR`(`/sessions/.../tmp`)は容量が逼迫しており
「No space left on device」で展開に失敗する。**必ず `TMPDIR=/tmp/dnxtmp` を指定すること。**

### 3.2 リポジトリ同期(マウント先→作業用へコピー)

```bash
rsync -a --delete --exclude='bin' --exclude='obj' /sessions/*/mnt/danoni_editor/ /tmp/repo/
```

ファイル編集ツール(Read/Write/Edit)はマウント先
(`C:\Docmenttn\danoni\danoni_editor` = `/sessions/*/mnt/danoni_editor/`)を直接見るが、
**bashでのビルドは `/tmp/repo` で行う**ため、編集後は毎回rsyncが必要。

### 3.3 ビルド・テスト

```bash
export DOTNET_ROOT=/tmp/dotnetsdk PATH=/tmp/dotnetsdk:$PATH \
       TMPDIR=/tmp/dnxtmp NUGET_PACKAGES=/tmp/nuget
cd /tmp/repo
dotnet build src/DanoniEditor.App -c Debug          # App層まで通せば全層ビルドされる
dotnet test tests/DanoniEditor.Core.Tests -c Debug
```

**完了基準**: ビルド0エラー0警告 + テスト全パス。本スレッドではこれを毎回実施している。

## 6. 本スレッドで得られた「ハマりどころ」の知見

次スレッドで同種の問題に遭遇した際の手掛かりとして記録する。

### 6.1 内部tickスケール(1680)と外部形式のtick単位の混同

**SKBネイティブは「4分音符=48tick」固定**であり、内部の1680スケールとは別物。
`PosScale = 1680 / 48 = 35` での変換が必須(`SkbExporter`は÷35、`SkbImporter`は×35)。

**この種の不具合は自ツール内の往復テストでは絶対に検出できない**
(エクスポート・インポート双方が同じ誤ったスケールを使うため往復では一致してしまう)。
外部形式を扱う際は必ず実データでの検証を計画に含めること。

**切り分けのコツ**: タイミング系の値(startNumber/BPM/blankFrame)が ground truth と完全一致
していれば、問題は位置データのみに限定できる。また、出力された生の値が特定の数(35等)で
すべて割り切れるかを見ると、スケール変換漏れを高確度で判定できる。

### 6.2 「実行時のCurrentTabを参照する」設計と、履歴・共有状態の相性の悪さ

`IEditAction` は Do/Undo の実行**時点**の `doc.CurrentTab` を対象に操作する。この設計自体は
シンプルで良いが、**履歴やタブ横断で共有される状態と組み合わさると静かにデータを壊す**。

同種の設計を追加する際は「この状態は本当にプロジェクト単位でよいか、タブ単位であるべきか」を
必ず検討すること。本スレッドでは以下2件が同じ根の不具合だった。

- `ChartProject.PlaybackStartFrame`(再生開始ライン) → タブ単位へ移行
- `UndoStack`(Undo履歴) → タブ単位へ分離

### 6.3 LostFocus確定方式とフォーカス残留

右パネルの数値項目は「フォーカスが外れた時点で確定」する方式。**モデルを読み書きする処理の
直前には必ず `CommitPendingEdits()` を呼ぶこと**。呼び忘れると「入力した値が保存されない」
「変更前タブへの編集が変更後タブへ書き込まれる」という形で表面化する。

新しく「モデルを読む入口」(エクスポート機能の追加、外部連携等)を作る際は、
`CommitPendingEdits()` の呼び出しを忘れないこと。

### 6.4 表示処理がモデルを書き換えていないか

②色設定タブの初期値自動補完不具合は、**表示用の値を組み立てる処理がついでにモデルへ
書き込んでいた**ことが原因だった。`Display*` 系(表示専用・モデル不変)と `Ensure*` 系
(実体化を伴う)を明確に分け、後者はユーザーの明示的な編集操作からのみ呼ぶこと。

### 6.5 staticな共有状態とテストの並列実行

`EditorClipboard` は static。xUnitは既定で**異なるテストクラス同士を並列実行する**ため、
同じstatic状態を触るテストクラスが複数あると不定期FAIL(フレーキー)を起こす。
`[Collection("...")]` + `[CollectionDefinition(..., DisableParallelization = true)]` で
直列化すること(`tests/.../Editing/EditorClipboardCollection.cs` が実例)。

**テストが落ちた際は、まず同じコードで複数回実行して再現性を確認すること。**
本スレッドでは3回連続パスによりフレーキーと断定できた。

### 6.6 大きなWebページの取得

danoniplus公式wikiは1ページが大きく、`web_fetch` がトークン上限で失敗することがある。
その場合は保存されたファイルに対して `grep` で該当箇所を絞り込み、必要な範囲だけ
`Read` の `offset`/`limit` で読むのが効率的。
