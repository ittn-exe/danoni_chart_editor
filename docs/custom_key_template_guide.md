# オリジナルキー種テンプレートの作り方

このドキュメントは、テンプレートエディタを使って自分だけのオリジナルキー種(いわゆる「カスタムキー」)を作り、danoniplus本体でも使えるようにするまでの手順を説明します。danoniplusの「カスタムキー」がどういう仕組みなのか分からなくても、この手順に沿えば作成できるように書いています。

## 1. そもそも「キー種テンプレート」とは何か

当エディタは、5key・7key・9key・23keyのような「キー種」ごとに、レーンの数・配置・見た目を定義した設定ファイル(`template/temp_{キー種ID}.json`)を持っています。これを「キー種テンプレート」と呼びます。譜面ビューの列構成、プレイテストの見た目、dos.txt出力時のデータ名などは、すべてこのテンプレートに基づいて決まります。

自分だけのオリジナルキー種を作るというのは、要するに「この設定ファイルを新しく1つ作る」という作業です。手でJSONファイルを書くこともできますが(`docs/template_format.md`にJSON形式そのものの仕様があります)、通常は「環境設定 > テンプレート」から開ける**テンプレートエディタ**というGUI画面で作成・編集します。このドキュメントはテンプレートエディタでの作成手順を説明します。

## 2. danoniplus本体の「カスタムキー」との関係

当エディタのキー種テンプレートは、あくまで**エディタの中だけで通用する設定**です。これだけでは、実際にdanoniplus本体(ブラウザで遊ぶゲーム側)で新しいキー種として遊べるようにはなりません。

danoniplus本体側にも、独自のキー種を追加できる「カスタムキー」という仕組みが別途あります。こちらはdos.txtのヘッダー、またはdanoni_settings.js等の共通設定ファイルに、`|keyCtrl9j=...|`のような専用のパラメータ行を書き足すことで実現されています。

つまり、オリジナルキー種を実際に本体で遊べるようにするには、次の2段階の作業が必要になります。

1. **当エディタのテンプレートエディタ**で、譜面を作るためのテンプレートを作成する(このドキュメントの本題)
2. 作成したテンプレートを、**「カスタムキー定義へエクスポート」機能**で本体互換の設定テキストへ変換し、本体側の設定ファイルへ貼り付ける

幸い、当エディタのテンプレートの各項目は、本体側のカスタムキー定義とほぼ1対1で対応するように設計されています。エクスポート機能を使えば、この変換作業はほぼ自動で行われます。

## 3. テンプレートエディタを開く

メインウィンドウの「環境設定」を開き、左側のカテゴリ一覧から「テンプレート」を選びます。既存のテンプレート一覧が表示されるので、「新規作成」ボタンを押すとテンプレートエディタが開きます(既存のテンプレートを選んで「編集」を押せば、そのテンプレートを元に編集することもできます)。

テンプレートエディタの画面構成は次の通りです。

- **左パネル**: テンプレート全体の設定(キー種ID・表示名・レーン間隔など)
- **中央**: レーン(キー1つ分)ごとのタブ。タブをドラッグ&ドロップで並び替えると、その並び順がそのままレーンの表示順になります
- **上部**: 現在のレーン並びでノート画像を並べたプレビュー

## 4. 全体設定を入力する

左パネルの「全体設定」で、以下の項目を入力します。

| 項目 | 意味 |
|---|---|
| `keyTypeId` | キー種の識別子。半角英数字1〜10文字。保存時のファイル名(`temp_{keyTypeId}.json`)にもなります。他のキー種と重複しない値にしてください(例: `myKey`, `10x`) |
| `keyTypeName` | 一覧等に表示される名前(例: `オリジナル10key`) |
| `comment` | 自由記述欄。何のためのキー種かメモしておくと後で分かりやすいです |
| `blank` (px) | 隣り合うレーン同士のステップゾーンの間隔。大きくすると横に広がります |
| `divideCnt` | 横一列に並べるだけの場合は `レーン数-1` を指定してください(後述の「中央揃え」参照)。上下2段に折り返す配置をする場合は折返し位置を指定します |
| `posMax` | 横一列に並べるだけの場合は `レーン数` を指定してください。折り返し配置の場合は折り返し後グループの基準値 |

`keyCount`(レーン数)は自動計算されるため、直接入力する項目はありません。レーンタブを追加した数がそのままレーン数になります。

### レーンの横並び順(posIndex)の考え方

各レーンには `posIndex` という「横位置の順番」を表す数値があります(レーンタブ側で設定、次章参照)。単純にレーンを横一列に並べるだけなら、`posIndex` に `0, 1, 2, 3...` と左から順に整数を振っていくだけで十分です。

もし「上段と下段に分けて配置したい」「特定のレーンだけ間隔を空けたい」といった複雑な配置をしたい場合は、`divideCnt`(この値を超えたposIndexのレーンは「折り返し後」として扱われる)と `posMax`(折り返し後グループの基準値、通常はposIndexの最大値と同じにする)を使います。この仕組みは、danoniplus本体側の `div`/`divMax` パラメータにそのまま対応しています。

具体的な計算式は次の通りです(プレイテスト画面のX座標もこの式で決まります)。

```
stdPos = posIndex - ((posIndex > divideCnt ? posMax : 0) + divideCnt) / 2
stepX  = blank * stdPos + (プレイ画面の幅 - 50) / 2
```

**重要: 横一列に並べるだけの場合でも `divideCnt`/`posMax` を `0` のままにしないでください。** `divideCnt=0`・`posMax=0`のままだと、この式は常にoffset=0になり、`posIndex=0`のレーンが画面中央に固定され、残りのレーンがそこから右へ一方向に並ぶ(中央揃えにならない)symptom(不具合)が発生します。横一列・中央揃えにしたい場合は、`divideCnt`に`レーン数-1`、`posMax`に`レーン数`を指定してください(例: 9レーンなら`divideCnt=8`・`posMax=9`)。こうすると`posIndex`の値に関わらず必ず`(0+divideCnt)/2`のoffsetが使われ、`stdPos`が`-(レーン数-1)/2`〜`+(レーン数-1)/2`の範囲で0を中心に対称になります(5key標準テンプレートの`divideCnt=4`・`posMax=5`と同じ考え方)。折り返し配置が必要になったら、既存の折り返し系キー種(23key等)のテンプレートを開いて数値の参考にするとよいでしょう。

## 5. レーンを追加する

中央パネル上部の「レーン追加」ボタンを押すと、新しいレーンのタブが1つ追加されます。追加したいレーン数だけこのボタンを押してください。各レーンタブでは、以下の項目を設定します。

| 項目 | 意味 |
|---|---|
| `laneId` | エディタ内部だけで使う識別子。dos.txt出力には出てきません(例: `left`, `key1`) |
| `dataName` | dos.txt出力時のベース名になります(例: `left` → `left_data`)。基本的に `laneId` と同じで問題ありません |
| `frzDataNameOverride` | フリーズのデータ名が「`frz` + `dataName`」という規則から外れる場合だけ指定します。通常は空欄のままで構いません |
| `keyAssign` | 実際のプレイキー割当(表示ラベル)。矢印キーなら `←`、文字キーなら `S` のように入力します。同じレーンに複数キーを割り当てたい場合は `/` で区切ります(例: `E/R`) |
| `keyboardInputKeys` | キーボードモード(エディタ内のSKB風キーボード入力)専用の入力キー。`keyAssign` とは別物です。「入力開始」ボタンを押してから実際にキーを押すと自動入力されます。矢印キー・Space・BackSpaceはエディタのカーソル移動に予約済みのため、ここには割り当てられません |
| `colorGroup` | 色グループ番号(整数)。同じ色にしたいレーン同士に同じ番号を振ります |
| `posIndex` | 横位置の順番(4章参照)。左から `0, 1, 2, 3...` のように振るのが基本です |
| `scrollDirection` | `down`(標準: ステップゾーンが下、ノーツは上から下へスクロール)か `up`(ステップゾーンが上、ノーツは下から上へスクロール) |
| `noteGraphic` | ノート画像の種類。`arrow`(矢印)・`onigiri`(おにぎり)等から選びます |
| `rotationAngle` | 矢印画像を使う場合の回転角(度)。左向き `0`、下向き `-90`、上向き `90`、右向き `180` が目安です(`noteGraphic` が `arrow` 以外のレーンでは使われません) |
| `engineLaneNum` | danoniplus本体側の内部レーン番号(整数、0始まり)。**キー種内で重複させないこと**。色指定(ncolor_data)がこの番号でレーンを識別するため、重複するとレーンを取り違えます |

不要になったレーンは、タブを選択した状態で「レーン削除」ボタンを押せば削除できます。

## 6. キーパターン(応用、任意)

danoniplus本体には、同じキー種に対して複数の物理キー配置(例: 矢印キー中心の配置と、DFJK等のキーボード中心の配置)を用意できる「キーパターン」という概念があります。左パネルの「キーパターン」セクションで「パターン追加」を押すと、`keyAssign`・`colorGroup`・`posIndex`・`scrollDirection`・`noteGraphic`・`rotationAngle`・`blank`・`divideCnt`・`posMax` の組を、パターンごとに別々の値として持たせることができます。

最初のうちはパターンを追加せず、既定パターン(パターン0)だけで作成することをおすすめします。慣れてから、必要に応じて追加してください。

追加したパターンは、8章の「カスタムキー定義へエクスポート」でそのまま出力されます(本体側の`$`区切り複数パターン記法に変換されます)。`chara`(読み込み変数名)だけはエディタ側でパターンごとに変えられないため、全パターンで同じ値が出力されます。

## 7. 保存する

すべての項目を入力したら、右下の「保存」ボタンを押します。`template/temp_{keyTypeId}.json` として保存され、以後プロジェクト作成時の「キー種」選択肢に表示されるようになります。

保存後は、実際に新規プロジェクトを作成してこのキー種を選び、以下を一通り確認することを強くおすすめします(入力値のチェックは行われないため、間違いがあってもエラーは出ず、見た目やプレイテストがおかしくなる形で症状が出ます)。

- 譜面ビューでレーンが意図した順番・間隔で並んでいるか
- プレイテストでノートが正しい向き・位置に表示されるか
- レーンをクリックしてノートを置き、正しいレーンにノートが入るか

## 8. 本体で使えるようにする(カスタムキー定義へエクスポート)

テンプレートが完成したら、「環境設定 > テンプレート」の一覧で該当のテンプレートを選び、「カスタムキー定義へエクスポート」ボタンを押します。開いたウィンドウで、必要であれば説明文(`keyHelpJa`/`keyHelpEn`、省略可)を入力すると、下のプレビュー欄に本体互換の設定テキストが表示されます。

「書き出し」ボタンを押すと、`template/カスタムキー定義_{keyTypeId}.txt` というテキストファイルとして保存されます。このファイルの中身をそのまま、dos.txtのヘッダー部、またはdanoni_settings.js等の共通設定ファイルへコピー&ペーストしてください(貼り付け先による書式の違いはありません)。

### このエクスポート機能が対応していない項目

以下の項目は、当エディタのテンプレートに対応する情報が無い、または本体側の書式に確証が持てなかったため、現バージョンのエクスポートでは出力されません(本体側の初期値・自動生成に任せる形になります)。

- `keyGroup`/`keyGroupOrder`(キーのグループ分け)
- 色・スクロール方向の名前付きパターンセット(`Cross`/`Split`等)。常に無名の1パターンのみ出力します
- 既存キーへのパターン追加(`appendX`)・別キーモード(`transKeyX`)。エクスポート機能は常に「新規カスタムキーを1から定義する」形で書き出します

これらが必要になった場合は、書き出したテキストファイルを直接手で書き足してご利用ください。

## 9. 実践: ゼロから4keyを作ってみる

具体例として、矢印なしの4つの文字キー(`D`, `F`, `J`, `K`)を横一列に並べただけの、シンプルな4keyオリジナルキー種を作ってみます。

1. 「環境設定 > テンプレート > 新規作成」でテンプレートエディタを開く
2. 全体設定: `keyTypeId=myDFJK`、`keyTypeName=オリジナル4key`、`blank=57.5`、`divideCnt=3`(レーン数4-1)、`posMax=4`(レーン数)
3. 「レーン追加」を4回押し、4つのレーンタブを作る
4. 1つ目のレーン: `laneId=d`、`dataName=d`、`keyAssign=D`、`colorGroup=0`、`posIndex=0`、`scrollDirection=down`、`noteGraphic=arrow`、`rotationAngle=0`、`engineLaneNum=0`
5. 2つ目のレーン: `laneId=f`、`keyAssign=F`、`posIndex=1`、`engineLaneNum=1`(その他は1つ目と同じ)
6. 3つ目のレーン: `laneId=j`、`keyAssign=J`、`posIndex=2`、`engineLaneNum=2`
7. 4つ目のレーン: `laneId=k`、`keyAssign=K`、`posIndex=3`、`engineLaneNum=3`
8. 「保存」を押す
9. 「環境設定 > テンプレート」の一覧から`myDFJK`を選び、「カスタムキー定義へエクスポート」でテキストを書き出す

これで、譜面ビュー上は左から D/F/J/K の4レーンが並んだシンプルなキー種の出来上がりです。矢印を使わない代わりに `noteGraphic` を全レーン `arrow` のままにしていますが、見た目にこだわりたい場合は `rotationAngle` を変えたり、`onigiri` 等の別画像に差し替えても構いません。

## 10. うまく動かないときのチェックリスト

- `keyTypeId` が他のキー種と重複していないか
- `engineLaneNum` がレーン間で重複していないか(重複すると色指定がレーンを取り違えます)
- `posIndex` が意図した横並び順になっているか(小さい方から左に並びます)
- `keyboardInputKeys` に矢印・Space・BackSpace等の予約キーを入れていないか
- `noteGraphic` に存在しない画像名を指定していないか(`./img/` 配下のファイル名と一致させる)
- エクスポートしたテキストを本体側へ貼り付けた際、`keyCtrl`(キー割当)の値が意図通りか(矢印記号は `Left`/`Down`/`Up`/`Right`、テンキーは `Numpad0`〜`Numpad9`等へ自動変換されますが、それ以外の特殊な入力を使っている場合はプレビューで必ず確認してください)
